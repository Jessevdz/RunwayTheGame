# Runway Documentation Site

This directory contains the public documentation site for **Runway**, built with [Astro](https://astro.build) and [Starlight](https://starlight.astro.build).

---

## 🏗️ Architecture & Project Structure

The documentation site is structured around Astro Content Collections, custom React visualization components, and Starlight theme customization:

```
docs-site/
├── astro.config.mjs         # Starlight configuration, base path (/docs), & integrations
├── package.json             # Dependencies and Astro lifecycle scripts
├── tsconfig.json            # TypeScript configuration
├── src/
│   ├── content.config.ts    # Starlight Content Collections definition (docsLoader & schema)
│   ├── components/          # Custom Astro & React components (interactive diagrams & header)
│   │   ├── anim.css         # Shared SVG animation keyframes and timing classes
│   │   ├── CaptureLoop.tsx  # Interactive challenge capture flow visualization
│   │   ├── ChartingPath.tsx # Waypoint graph pathing & connectivity visualization
│   │   ├── CoinRushClock.tsx# Race clock & scoring mechanics visualization for coin rushes
│   │   ├── OpenForWhom.tsx  # Waypoint clearance vs. veto bypass comparison matrix
│   │   ├── RaceAnimation.tsx# Animated board racing demonstration loop
│   │   ├── Roadblock.tsx    # Power-up obstacle placement & clearance visualization
│   │   └── SiteTitle.astro  # Header wordmark linking back to app root
│   ├── content/
│   │   └── docs/            # Markdown & MDX documentation content source files
│   │       ├── index.mdx            # "What is Runway?" (Overview, rules, modes, grading)
│   │       ├── design-a-board.mdx   # "Design a board" (Living map editor guide)
│   │       ├── set-up-a-race.mdx    # "Set up a race" (Host lobby & player entry guide)
│   │       └── run-it-locally.mdx   # "Run your own instance" (Docker & local hosting guide)
│   └── styles/
│       └── departure.css    # Departure design system typography & Starlight theme overrides
└── dist/                    # Static site build output (generated by `npm run build`)
```

---

## 📖 Content & Sidebar Navigation

The site documentation is managed in `src/content/docs/` and configured in `astro.config.mjs`:

*   **What is Runway? (`index.mdx`):** Comprehensive introduction to core concepts (boards, waypoints, challenges, coins, power-ups, game modes, and evidence grading modes).
*   **Design a board (`design-a-board.mdx`):** Guide for authoring interactive maps, drawing waypoints and roads, writing challenges and grading criteria, and publishing to the gallery.
*   **Set up a race (`set-up-a-race.mdx`):** Guide for hosting multiplayer games, configuring lobby parameters, distributing join codes/QR links, and starting solo time trials or casual runs.
*   **Run your own instance (`run-it-locally.mdx`):** Infrastructure guide for self-hosting Runway with Docker Compose, MinIO S3 evidence storage, PostGIS database, AI referee keys, reverse proxies, and volume backups.

## 🧩 Interactive Visual Components

Custom React and Astro components embedded within MDX pages visually illustrate core game mechanics:

| Component | Purpose |
| :--- | :--- |
| `RaceAnimation.tsx` | Visualizes a live board race between competing teams moving along waypoints. |
| `CaptureLoop.tsx` | Demonstrates the step-by-step waypoint arrival, GPS check, and photo submission loop. |
| `ChartingPath.tsx` | Illustrates graph-based pathing and road connectivity between waypoints. |
| `OpenForWhom.tsx` | Clarifies the distinction between completing a challenge (unlocks for all) vs. vetoing (unlocks only for your team). |
| `CoinRushClock.tsx` | Explains placement bonuses and race countdown dynamics when crossing the finish line in coin rush modes. |
| `Roadblock.tsx` | Illustrates roadblock power-up deployment, detour paths, and photo-clearing mechanics. |
| `SiteTitle.astro` | Custom Starlight header brand wordmark providing seamless navigation back to the main game application root. |

## 🎨 Design System & Theming

The documentation site adopts Runway's **Departure** design aesthetic via `src/styles/departure.css`:

*   **Typography:** Google Fonts loaded in `astro.config.mjs` including `Archivo Black` (Announce), `Inter` (UI/body), `JetBrains Mono` (Data/code), and `Playfair Display` (Narrate).
*   **Theme Bridge:** Maps Departure design tokens (`--navy-*`, `--indigo-*`, `--amber`, `--signal`, etc.) onto Starlight's `--sl-*` variables for seamless light/dark mode consistency with the main application.

## 🛠️ Development & Build Commands

Run these commands from inside the `docs-site/` directory:

```bash
# Start Astro dev server for documentation (runs on http://localhost:4321, base /docs/)
npm run dev

# Run Astro type-checking (astro check) and build static bundle into dist/
npm run build

# Preview production build static files locally
npm run preview
```

### 🔗 Integration with Frontend Workflow

You can also control the documentation site directly from the `frontend/` directory:

```bash
# From frontend/: launch Astro dev server
npm run dev:docs

# From frontend/: build static documentation for distribution
npm run build:docs
```

To direct in-app documentation links to your local Astro dev server during frontend development, add the following to `frontend/.env` and restart `npm run dev`:

```env
VITE_DOCS_BASE_URL=http://localhost:4321/docs/
```

## 🐳 Production Deployment & Nginx Routing

In production, the documentation site is built as part of the multi-stage `Dockerfile`:

1. **Build Stage (`docs-builder`):** Compiles static assets to `docs-site/dist` using `npm run build`.
2. **Nginx Integration (`frontend` image):** Static files are copied to `/usr/share/nginx/html/docs` and served alongside the frontend SPA from the same origin under the `/docs/` path.
3. **Nginx Routing:** `frontend/nginx.conf` configures exact redirection from `/docs` to `/docs/` and serves `/docs/404.html` for missing documentation paths to avoid unintended SPA fallback routing.
